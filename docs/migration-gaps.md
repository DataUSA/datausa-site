# Migration gaps and decisions

Running list of behaviour that differs from the legacy site, was deliberately simplified, or still
needs work. Updated as milestones land. "Legacy" = the Canon app at `../datausa-site` / localhost:3300.

## Open

| # | Area | Gap | Plan |
|---|---|---|---|
| G1 | Images | Profile splash/thumb images (722 MB on the legacy VM) are hot-linked from `https://datausa.io/api/profile/<slug>/<member>/<size>` via `NEXT_PUBLIC_IMAGE_BASE_URL`. They stop working when the legacy app is switched off. | Before cutover: copy `static/images/profile/{splash,thumb}` to object storage or a static host and point the env var at it (the URL shape stays `/api/profile/...` or a new base). User decision 2026-10-09: do not move them yet. |
| G2 | Prism DB | PeoplePrism registrations are written to the legacy Postgres server (`PRISM_DATABASE_URL`, same host as the CMS DB). | Keep that database online or migrate the `prism_submissions` table; the app needs no other database. |
| G4 | Search ranking | Legacy ranked with a lunr index built at boot; the rewrite uses SQLite FTS5 prefix matching with the same post-ranking heuristics (exact/prefix boosts, zvalue weight). Results are very close but not byte-identical. | Compare top-10 results for common queries in Phase 7. |
| G5 | Popular reports | The home page's "Recent popular reports" come from Google Analytics 4 when `GA_KEYFILE` points at a service-account key (REST + JWT, no SDK); the key file is not present on the development machine, so that path has only been exercised against the fallback (curated defaults). | Verify on the VM with the production key file before cutover. |
| G6 | Deployment | PM2 ecosystem, Nginx snippet, cutover/rollback docs. | Phase 8. |

## Resolved or accepted differences

| # | Area | Difference | Rationale |
|---|---|---|---|
| A1 | `/api/data` logic layer | Legacy generator 127 ("Election - Electoral Votes") and 15 charts still call `/api/data`, which has been a 404 in production since the logic layer was removed. The rewrite returns the same 404 in-process, so the dependent variables and charts stay hidden exactly as they are today. | Faithful to production; the charts could be rewritten against Tesseract later. |
| A2 | Generator 728 | "Household Income by Race" requests two hierarchies of the same dimension and Tesseract answers 400, on the legacy site too. | Faithful. |
| A3 | Neighbour ordering | The legacy site listed neighbouring states in Postgres primary-key (geoid) order; the geoservice returns them by proximity. The rewrite sorts by geoid to keep the generated sentence identical. | Parity. |
| A4 | Sloppy-mode globals | Several CMS chart bodies assigned undeclared variables (`dataMales = …`). The converter declares them explicitly; behaviour unchanged. Genuine legacy defects are recorded in `scripts/legacy-export/patches.ts` with notes. | Documented. |
| A5 | Redirect status | Raw-id and crosswalk redirects answer 308 (issued by `src/proxy.ts` before rendering) instead of the legacy 301; both are permanent and SEO-equivalent. Unknown reports answer a real 404 the same way. | Framework default; see architecture decisions. |
| A6 | View Data table | The legacy Blueprint table with per-measure unit formatting became a plain HTML table (first 500 rows) plus full CSV download; CSV is downloaded directly rather than zipped. | Allowed simplification. |
| A7 | Save Image | PNG uses `@d3plus/export`; SVG serialises the chart's SVG element directly. | Same outcome. |
| A8 | Data cart | Already disabled in the legacy UI (`cartEnabled = false`); not ported. | Dead feature. |
| A9 | Shared d3plus theme | d3plus 4 warns once per chart class about theme keys it does not use (axis styling on a map, tiles on a bar chart); warnings are silenced with `configWarnings(false)`. | Theme is intentionally shared, as in legacy. |
| A11 | Citizenship chart (viz 430) | The CMS code spread a URL string into characters (`...dataNation`), so production requests ~190 one-letter URLs per county page and the chart shows "No Data Available". Patched to a single URL (`scripts/legacy-export/patches.ts`); the chart island also drops such fragments defensively. | Bug fix; recorded as a content patch. |
| A10 | Subnav dropdown | Hover/focus dropdowns are rebuilt without Blueprint; visuals follow the legacy CSS. | Allowed simplification. |
| A12 | Chart container sizing (fixed) | The first builds forced `height: 100%` on every child of the chart container. d3plus 4 appends the map attribution (`div.d3plus-attribution`) and control panels to that container and measures them when it claims margins, so maps with basemap tiles got a negative inner height (`<svg> attribute height: A negative value is not valid` in the console) and drew nothing but their timeline. The island stylesheet now sizes only the container itself (`src/components/viz/VizIsland.module.css`); `scripts/regression/harness/` is the stand-alone d3plus page used to bisect it. | Fixed; no console errors remain on the sampled reports. |
| A13 | Glossary formulas | KaTeX was replaced by native MathML for the three glossary formulas (no dependency, same content). | Allowed simplification. |
| A14 | Data sources page | Blueprint collapsible buttons became native `<details>` elements styled the same way; the grouping of Tesseract cube annotations is unchanged. | Allowed simplification. |
| A15 | Classifications table | The Blueprint data table became a plain HTML table with a sticky header in a scrolling container, with every member linked to its report. | Allowed simplification. |
| A16 | Icons | Icons that CSS recolours (dimension and feature icons) are inlined server-side from `public/` (`src/lib/inline-svg.ts`), replacing react-inlinesvg; pages that repeat an icon hundreds of times (search) use one SVG sprite with `currentColor`. Files over 20 KB (raster-wrapping SVGs) stay `<img>`s. | Same visuals, smaller HTML. |
| A17 | d3plus 4 defaults | d3plus 4.5–4.7 enable features the legacy d3plus 2 charts never had: in-chart table view, search box and minimap, zoom on every chart type, inset legends, size legends, shared Plot tooltips, motion trails, and unloading charts that scroll out of view. The shared theme (`src/lib/viz/theme.ts`) turns them off (`tableView`, `search`, `minimap`, `legendInset`, `sizeLegend`, `tooltipShared`, `detectVisibleUnload`, `shapeConfig.Circle/Rect.trail`) and the chart island sets `zoom: false` for everything but maps, so the CMS configs render as designed. d3plus 4 also keys legend entries on its `color` accessor (default: the first groupBy level), which merged per-category legends into their parent groups and broke label code that expects strings; `color: false` keys legends on the resolved fill again, as d3plus 2 did. Individual CMS configs can still opt in. d3plus 4 also lets a theme's generic `shapeConfig.fill` override the Geomap's colour-scale fill (d3plus 2 gave the chart's Path fill precedence), so the theme defines `shapeConfig.Path.fill` (`pathFill`: colour scale, else `topojsonFill`) to keep choropleths shaded by value. Three more d3plus 4 defaults are reverted for parity: `domainTicks: false` on every axis (d3plus 4 forces the data min/max into the ticks, e.g. a "146,100" label), `labelConfig.split = legacySplit` (d3plus 4 hyphenates words that do not fit; the legacy charts dropped them), and axis titles upper-cased in the chart island because d3plus 4's text nodes carry no `d3plus-Axis-title` class for the legacy CSS rule to style. Bar labels also get `lineHeight` equal to their font size: d3plus 4's legend, timeline and axes leave bars a few pixels thinner, and a label is only drawn when its line height fits inside the bar minus padding, which silently dropped the age labels off the population pyramids (visible on embeds and anchor-link landings; found with `scripts/regression/harness/bar.ts`). | Keyed to the d3plus CHANGELOG (4.0, 4.5, 4.6, 4.7); audited with `scripts/regression/probe-d3plus-warnings.mjs`. |
| A18 | Section icons | The CMS names section icons from the Blueprint icon set ("pulse", "briefcase"…), which the legacy site rendered through `@blueprintjs/core`. The eight icons the content uses are exported as SVG files in `public/icons/blueprint` (Apache-2.0, see the LICENSE there) and inlined so CSS colours them, with no Blueprint dependency. | Same glyphs, no UI framework. |
| A19 | Other report families | `cip`, `naics`, `soc`, `university` and `napcs` are extracted by the same tool; their attribute resolvers (`src/content/reports/*/attributes.ts`, lookups in `src/lib/content/lookups.ts`) and the legacy endpoints they call (`/api/university/{commonJobLookup,highestWageLookup,commonIndustryLookup}`, `/api/napcs/:id/sctg`, occupation `/api/neighbors`) are ported. Text variables match the legacy payloads exactly for Restaurants & Food Services (195/195), Registered Nurses (345/345), Computer Science (469/469) and Harvard University (431/431). | Verified with `scripts/regression/compare-variables.mjs`. |
| A20 | NAPCS freight sections | For "Research and development services" the production site's `/api/napcs/54301/sctg` answers `[]` and its `sctg` attribute is empty, so the freight (FAF) generators return nothing and those sections are hidden. The repository's `nacps2sctg.json` (the file the legacy app ships) does map the product, so the rewrite computes the freight variables and shows the sections. Products whose crosswalk is empty behave as before. | Data from the versioned crosswalk; differs from the deployed site only where its crosswalk is stale. |
| A21 | Charts are mounted by our own renderer | `@d3plus/react`'s Renderer is not StrictMode-safe: in development React's simulated unmount/remount re-ran its render effect on the same d3plus instance while the chart's data was still loading, and two overlapping d3plus renders apply the axis margins twice (plots half their height, bar labels gone). Charts that first rendered off-screen deferred drawing until visible and dodged it, which is why scrolled captures looked right while embeds and anchor-link landings did not. `src/components/viz/ChartRenderer.tsx` mounts `@d3plus/core` charts directly, deferring the render by a frame so the simulated unmount cancels it; the island also passes the figure's `width`/`height` explicitly and waits for the chart fonts, so d3plus never measures, observes or redraws on its own. `@d3plus/react` is no longer a dependency. | Fixed on our side (development only in effect; production builds never double-invoke effects). |
| A22 | Map opacity and tooltips under d3plus 4 | Three d3plus 4 behaviours changed every map. (1) Geomap paints topojson paths with `fill`, `stroke`, `strokeWidth` and `opacity` only, so the theme's `fillOpacity: 0.75` / `strokeOpacity: 0.25` (and the About maps' 0.5 neighbours) were dropped; `geomapShapeConfig` in `src/lib/viz/theme.ts` folds both opacities into the colours, and turns a fully transparent fill into `none` so an outline drawn over other shapes does not swallow their hover. (2) Every topojson path gets a tooltip, even with no data row (titled "Other Values"); the theme's `tooltip` accessor turns it off for data-less shapes, as d3plus 2 did. (3) Tooltips are `position: fixed` without a transform, so the legacy `position: fixed` icon badge was placed against the viewport and never seen; it is `position: absolute` now. | Matches legacy rendering. |
| A23 | About map | The legacy About map (viz 1 for geographies, 136 for universities) had no tooltip: its topojson carries ids only. The rewrite joins the shapes to `GET /api/geo/names` (id and name from the dimensions database, by id list or id prefix) and shows the name of the shape under the cursor; state outlines behind places and metro areas stay silent. The map is the legacy 300x200 thumbnail (`--viz-min-height` overrides the 400px chart minimum). On phones the legacy layout squeezed the side column to ~110px, cutting the breadcrumbs mid-line and hiding the map; the rewrite shows both. `PUMA.json` is rebuilt from the Census Bureau's 2020 PUMA boundaries (see A24). Content now references `Msa.json` and `birthplace.json` by their real names: `MSA.json` / `Birthplace.json` only resolve on a case-insensitive file system. | Improvement, by request. |
| A24 | PUMA shapes | The legacy `PUMA.json` held 2,380 shapes of an older boundary vintage; 952 of their ids exist in neither the dimensions database nor Tesseract, so those areas had no data on the PUMA choropleths (Massachusetts drew 13 of its PUMAs) and no page to link to. The file is rebuilt from the Census Bureau's 2020 cartographic boundary file (`cb_2020_us_puma20_500k`, the current vintage: PUMAs are redrawn once a decade) by `scripts/topojson/build.sh puma`: 2,487 shapes, same format (`pumas` object, Tesseract ids), simplified to the old file's level of detail (801 KB, 273 KB gzipped). It covers every PUMA id Tesseract returns for 2014-2024. Only Guam's shape has no data and no name. See A25 for the 16 PUMAs the legacy search table lacked. | Fix, by request. |
| A25 | Members missing from the legacy search table | Tesseract has data for 16 PUMAs (AR, KS, OH, TN, WI) and 8 congressional districts created by the 2022 redistricting (CO-8, FL-28, MT-1, MT-2, NC-14, OR-6, TX-37, TX-38) that `canon_cms_search` never listed, so the legacy site answers "Member not found" for them: no report, no search result, no link from neighbours. The rewrite adds them in `data/members-additions.jsonl`, which `build-dimensions.ts` merges before `members.jsonl` (an exported row with the same key wins, so a later re-export supersedes them). Names are Tesseract's captions and slugs follow the existing rule. `zvalue` (search ranking) is an estimate: existing values are linear in 2017 ACS population within a level (r = 0.997), and that line is applied to each new member's 2024 population. Their shapes come from the rebuilt `Districts.json` (A26). | Improvement, by request. |
| A26 | Congressional district shapes | The legacy `Districts.json` held the districts in force before the 2022 redistricting: it lacked the 8 new districts and still drew 8 abolished ones (CA-53, IL-18, MI-14, MT at large, NY-27, OH-16, PA-18, WV-3), and every redrawn district had its old outline. It is rebuilt from the Census Bureau's `cb_2025_us_cd119_500k` (441 districts of the 119th Congress) by `scripts/topojson/build.sh districts`; it covers every district Tesseract returns for 2022-2024 except the "not defined" remainders. Only the About map draws this file in practice (the House map, viz 184, needs `houseMulti` inside a section that is only shown for a single representative, on both sites). The 8 abolished districts keep their report pages (data to 2021) with no shape to highlight. | Fix, by request. |
| A27 | Geoservice district layer | The geoservice still holds the districts in force before the 2022 redistricting. It answers `[]` for the 8 new districts (`relations/intersects` and `neighbors`), which left their pages without a state breadcrumb, senators, representative or Civics section, and made `/api/civic/representative/<id>` return every state's district of that number. The rewrite now reads the state from the id when the geoservice returns none (`stateOf` in `src/lib/api/geoservice.ts`, used by `intersects` and by generator 23): counties, places, tracts, PUMAs and districts carry their state's FIPS code. Not fixed here: those 8 pages still have no neighbours, and for the other districts the geoservice's neighbours and overlaps describe the old outlines (compared with the rebuilt `Districts.json`, 297 of 433 districts lack at least one current neighbour and 52 list an abolished one; Missoula County, MT still maps to the at-large district). | Fix, by request. The geoservice layer itself is for the data team. |
| A28 | Hero candidate names on phones | The legacy stylesheet shrank senator and representative names in the hero to 16px at 400px and below (`Splash.css`); the port had missed the rule, so a long name (John Hickenlooper) overflowed a 390px screen by 10px. Rule restored in `Stat.module.css`. | Regression fix. |
| A29 | Line and area colours | d3plus 2 called a Line's or Area's style accessors (`stroke`, `fill`, `strokeWidth`...) with the shape's first data point; d3plus 4 calls them with all of the shape's points merged into one object (`Shape._styleVal`), and the merge sums numbers. A numeric id therefore stops identifying anything (`"Kaiser Coverage ID": 1` over twelve years becomes 12), so configs that colour by it got no colour or the fallback: "Uninsured People" (viz 401) drew only Medicaid, whose id is 0, and four of Harvard's comparison charts (timeframe, endowment, salaries, instructional salaries) lost their highlighted line. `src/lib/viz/d3plus-compat.ts` restores the d3plus 2 rule for every chart by replacing that one private method; re-check it when upgrading `@d3plus/core` (written against 4.7.0). Colours verified against legacy on those charts and on the presidential stacked area, except endowment, whose legacy chart did not draw its lines when probed. | Regression fix. Worth changing in d3plus itself. |
